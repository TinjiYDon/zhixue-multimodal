## 一、结论速览

| # | 问题 | 实测数据 | 影响 |
|---|---|---|---|
| 1 | **转写结果不可复现** | 同一输入两次运行得 37 / 41 段 | 学生会看到不同字幕；模型对比与参数调优结论失效 |
| 2 | 时间轴无法区分真实与占位 | 真实转写的 message 与占位同为 `fixture/job hook` | 排障误判，用户无法判断内容可信度 |
| 3 | 失败任务仍返回非空时间轴 | 静音轨任务 `failed`，却返回 2 条占位 + 120 s | 一节失败的课看起来「有内容」 |
| 4 | 容量上限即将触顶 | 13 分钟素材占 200 MiB 上限的 **94.6%** | 约录到 14 分 45 秒即被拒 |
| 5 | 长素材存在满刻度削波 | 峰值 **0.00 dBFS** | 谐波失真直接损害识别准确度 |
| 6 | 识别错误集中在专业术语 | 8 处实例中 4 处为术语/人名 | 课程内容的关键概念被写错 |
| 7 | VAD 收益分场景，一刀切不合适 | 静音省 99.4%，语音密集反慢 11% | 统一开关无法兼顾两端 |
| 8 | 课件侧信息未被利用 | 时间轴 slides 恒为 1 条占位 | 多模态优势未发挥，术语错误无从纠正 |

> **优先级最高的一项**：转写结果的随机性。它不会表现为报错，也不会立刻被察觉，
> 但会让后续所有准确度评测与模型对比失去基准——**这是当前最需要先处理的隐性风险**。

## 二、测试环境与方法

### 2.1 环境

| 项 | 值 |
|---|---|
| 主机 | AMD Ryzen 5 5600H · 6 核 12 线程 · 15.4 GiB RAM |
| Python | 3.13.14 · Windows |
| 音频解码 | PyAV（wheel 内置 FFmpeg 库，无需系统安装 ffmpeg） |
| ASR | faster-whisper · CTranslate2 · CPU int8（不需要 torch / CUDA） |
| 系统依赖 | 无 ffmpeg 可执行文件 · 无 Docker / MinIO |

### 2.2 方法

1. **容器级解码取证**：读取编码、分辨率、帧率、音轨参数与逐帧 PCM，不依赖目测。
2. **能量闸门实测**：对真实视频解码出的 16 kHz 单声道音频直接测量能量结构。
3. **ASR 实测**：`base` 与 `small` 两档各跑一遍，关闭 VAD 以测最坏情况。
4. **端到端**：每段素材新建课程，经 `POST /api/v1/jobs` 触发处理，完成后读时间轴。
5. **对照实验**：静音轨做「闸门 / VAD 开 / VAD 关」三路对比；可复现性做「默认 / 2 线程 / 1 线程」三路对比。

## 三、四类视频在平台的运行表现

### 类型 1 · 正常短视频（6 分钟）—— 典型工作路径

`正常短视频_720p6min.mp4` · 385.09 s · 1280×720@25 · 84.20 MiB

| 阶段 | 观测结果 |
|---|---|
| 音频抽取 | 产出单声道 16 kHz WAV |
| 能量闸门 | 有效帧 **57.90%**，RMS −27.97 dBFS，峰值 −3.52 dBFS，最长静音 8.04 s → 放行（0.55 s） |
| ASR（base） | **37 段 / 1384 字**，48.75 s，9.97× 实时 |
| 时间轴 | 41 条字幕 · 时长 378.98 s |
| 任务状态 | `done` |

**质量风险点**

- `compression_ratio_max = 2.386`，紧贴 Whisper 自带的 2.4 重复阈值；
- 单段 `no_speech_prob` 最高 **0.9779**，即模型认为该段 98% 无语音，却仍输出了文本。

**判断**：这是平台主力场景，链路健康。但两项「幻觉前兆」指标已接近告警线，目前**没有任何机制会拦下它们**。

---

### 类型 2 · 正常长视频（13 分钟）—— 压力路径

`正常长视频_720p13min.mp4` · 836.97 s · 1280×720@25 · 189.21 MiB

| 阶段 | 观测结果 |
|---|---|
| 能量闸门 | 有效帧 **65.11%**，RMS −19.64 dBFS，峰值 **0.00 dBFS**，最长静音 8.22 s → 放行（1.25 s） |
| ASR（base） | **77 段 / 2764 字**，109.97 s，8.86× 实时 |
| 时间轴 | 77 条字幕 · 时长 831.76 s · slides 恒为 1 |
| 任务状态 | `done` |

**两个需优先处理的约束**

1. **峰值命中 0.00 dBFS —— 满刻度削波**。波形顶部被削平会产生谐波失真，直接影响识别；其 RMS 比另两段语音素材响 8～11 dB。这是**不换模型就能改善准确度**的点。
2. **容量告急**。189.21 MiB 已占 200 MiB 上限的 **94.6%**，按该样本码率（1896 kbps）仅剩约 **48 秒**余量，即录到约 **14 分 45 秒**就会被拒。

**判断**：无 GPU 下 110 s 出稿，长素材成本可接受；但容量与削波是必须先处理的硬约束。

---

### 类型 3 · 静音轨视频 —— 拒绝路径

`异常视频无音频版_720p6min.mp4` · 385.00 s · 135.13 MiB

**需要先纠正一个命名误解**：它**不是没有音轨**，而是有一条完整的 AAC 48 kHz 双声道音轨，但解码后**峰值为 0**，全部样本为零——属于**数字静音轨**。

这与「缺音轨」是两种不同故障，需要不同的修复方式：

| 故障 | 成因 | 修复方向 |
|---|---|---|
| 数字静音轨 | 录制时麦克风未开启 | 提示录制端检查设备 |
| 缺音轨 | 导流/转码时丢轨 | 检查上传与转码链路 |

因此建议**在错误分类上把二者分开**，否则用户拿到「没有语音」的提示，无从判断该查哪一环。

| 阶段 | 观测结果 |
|---|---|
| 能量闸门 | 有效帧 **0.00%**，RMS 无信号，峰值 无信号，最长静音 **385.02 s** → 拒绝（0.42 s） |
| ASR | 未执行（在模型加载前被拦下） |
| 时间轴 | 2 条占位 · 时长 120 s |
| 任务状态 | `failed`，错误信息指向「未检出可识别语音」 |
| 任务耗时 | **1.63 s** |

#### 三路对比：为什么需要能量闸门

| 处理路径 | 耗时 | 产出 | 说明 |
|---|---:|---|---|
| **能量闸门**（标准库逐帧能量） | **0.42 s** | 拒绝 | 零成本挡住纯静音 |
| VAD 开启 | 0.94 s | 0 段 | 省下 153.83 s（99.4%） |
| VAD 关闭 | **154.77 s** | **0 段** | 烧掉 154.77 s 且毫无产出 |

**判断**：闸门把这段素材的成本从 **154.77 s 压到 0.42 s**（**368 倍**），且比 VAD 快一倍以上、不引入任何模型依赖。这是当前**性价比最高的一项机制**。

**残留问题**：任务已 `failed`，课程时间轴却仍返回 2 条占位与 120 s 时长。占位文案已标注「（占位）」，但**前端若不据此隐藏，一节失败的课看起来仍然有内容**。

### 类型 4 · 极短片段（37 秒）—— 边界场景

`异常视频短片段版_720p37s.mp4` · 37.25 s · 13.17 MiB

| 阶段 | 观测结果 |
|---|---|
| 能量闸门 | 有效帧 64.73%，RMS −30.21 dBFS，峰值 −8.69 dBFS，最长静音 1.14 s → 放行（0.054 s） |

| 任务状态 | `done` |

**判断**：短片段吞吐最高、成本最低，适合作为快速回归与模型对比的固定基座。

## 四、闸门与 ASR 的实测特性

### 4.1 闸门自身开销（逐帧能量计算）

| 音频规模 | 耗时 | 吞吐 |
|---|---:|---:|
| 385 s（6.16 M 样本） | 0.42 / 0.55 s | 约 12 M 样本/秒 |
| 837 s（13.39 M 样本） | 1.25 s | 约 11 M 样本/秒 |

开销随时长**线性增长**：当前实现下两小时录播会到 10 秒级。

### 4.2 模型档位：升档并不单调变好

| 样本 | base 段/字 | base 速度 | small 段/字 | small 速度 | base logprob | small logprob |
|---|---|---|---:|---|---:|---:|---:|
| 短片段 37s | 15 / 164 | 11.74× | 13 / 164 | 4.17× | −0.177 | **−0.120** |
| 正常短 6min | 37 / 1384 | 9.97× | 127 / 1240 | 4.29× | −0.144 | **−0.084** |
| 正常长 13min | 77 / 2764 | 8.86× | 261 / 2600 | 3.92× | **−0.150** | −0.206 |

`small` 在短素材上更准，但**慢 2.3～2.8 倍**；在 13 分钟素材上 logprob 反而**更差**。

**结论**：升档必须按素材与场景分别验证，**不应默认设成更大模型**。

### 4.3 VAD 的收益是分场景的

| 场景 | VAD 关闭 | VAD 开启 | 结论 |
|---|---:|---:|---|
| 静音轨（6min） | 154.77 s | **0.94 s** | 省 99.4% |
| 语音密集（6min） | 89.67 s | 99.84 s | **反而慢 11%** |

正确的分层是：**闸门先以近似零成本挡掉纯静音，VAD 只留给「语音与长静音混排」的场景**。

## 五、识别错误实例

以下均为实测产出字幕中的**实际文本**：

| 模型输出 | 正确内容 | 错误类型 |
|---|---|---|
| `TedCard` | Ted Codd | 专有名词 · 关系模型提出者 |
| `榴栏器` | 浏览器 | 形近音近 |
| `真相改差` | 增删改查 | 术语 |
| `纸征` | 指针 | 同音 |
| `偶合度` | 耦合度 | 术语 |
| `支撑议体` | 支撑一体 | 同音 |
| `数学医这么课` | 数学这门课 | 插入错误 |
| `不经常的模块` | 不是一种普通的模块 | 整句失真 |

**八处错误中有四处是专业课术语或人名**，而这类词恰好**出现在课件幻灯片上**。

这是本项目「多模态」最直接的收益点：把课件文字作为热词或初始提示传给 ASR，**不需要更大的模型**即可纠正。

### 5.1 转写随机性：优先级最高的隐性风险

同一文件、同一进程、同一模型、**输入音频逐字节相同**（已验证两次抽取的 WAV 同 sha256、同 12,322,860 字节），连续两次运行：

| 线程设置 | 两次运行段数 | 可复现 | 6min 耗时 | 实时倍率 |
|---|---|---|---|---|
| 默认（多线程） | 41 / 37 | ✗ | 44.6 / 47.4 s | 约 9.97× |
| `cpu_threads = 2` | 37 / **82** | ✗ | 54.5 s | 7.07× |
| `cpu_threads = 1` | **37 / 37 · 文本 0 处差异** | **✓** | 72.2 / 73.4 s | 5.82× |

**根因**：CTranslate2 的 int8 矩阵乘在多线程下浮点归约顺序不定。（已排除解码因素——抽取产物逐字节相同。）

**影响面**

- 学生会看到**不同的字幕**；
- 同一任务的重复执行无法命中缓存；
- **对比两个模型或两组参数时，无法判断差异来自改动还是随机性** ← 最危险。

**对照实验的结论**：把线程数固定为 1 可完全消除差异（段数与逐段文本均一致），代价是约慢 1.6 倍。

## 六、优化建议

### P0 · 可信与可用（建议先做）

#### 1. 消除转写随机性

| | 内容 |
|---|---|
| **问题** | 同一音频重复转写得到不同分段与文本，根因为 int8 多线程归约顺序不定 |
| **建议** | 暴露线程数配置项，并提供「可复现」取值（=1）。**评测与回归固定为 1**，生产转写保留默认多线程以保吞吐 |
| **预期收益** | 评测结论与模型对比变得可信；学生端字幕稳定；同一任务可安全重试 |
| **代价** | 可复现模式在 6 分钟素材上慢约 1.6 倍（44.6 s → 73.4 s） |

> 这是唯一一项「不做则其他准确度工作都失去度量基准」的改动。

#### 2. 区分真实转写与占位时间轴

| | 内容 |
|---|---|
| **问题** | 真实转写入库后，时间轴 message 仍为 `timeline from fixture/job hook (Wave3)`；该文案由真实与占位共用的构造函数生成，接口层面**无法区分一条时间轴是真实转写还是演示占位** |
| **建议** | 让时间轴构造函数显式接受来源标记，并在接口暴露 `data_source` 字段供前端展示 |
| **预期收益** | 排障时不再误判；前端可对占位内容给出明确提示；演示与生产数据不混淆 |

#### 3. 失败任务的时间轴应显式表达失败

| | 内容 |
|---|---|
| **问题** | 静音轨任务状态为 `failed`，课程时间轴仍返回 2 条占位与 120 s 时长 |
| **建议** | 任务失败时返回空 cues 加明确状态，由前端提示「转写未完成」 |
| **预期收益** | 失败的课不再看起来「有内容」；用户能及时知道需要重新录制 |

#### 4. 传输与请求超时分离

| | 内容 |
|---|---|
| **问题** | 对象存储客户端读超时为 5 s，是为小请求设定的；189 MiB 对象在慢链路上若单次读停顿超时会导致下载失败 |
| **建议** | 为下载路径单独配置更宽松的读超时 |
| **预期收益** | 大文件上传不再因瞬时网络抖动整体失败 |

#### 5. 容量上限与分片上传

| | 内容 |
|---|---|
| **问题** | 13 分钟素材已占 200 MiB 上限的 94.6%，按该码率仅剩约 48 秒余量（约 14 分 45 秒触顶） |
| **建议** | 提高上限，或改为分片上传 |
| **预期收益** | 支持完整课时（45 分钟以上）的录播；避免长课被直接拒绝 |

### P1 · 准确度

#### 6. 音频前处理补齐

| | 内容 |
|---|---|
| **问题** | 13 分钟素材峰值达 **0.00 dBFS**（满刻度削波），RMS 比另两段响 8～11 dB |
| **建议** | 加入 EBU R128 响度归一化 + 80 Hz 高通 |
| **预期收益** | 消除可直接消除的谐波失真；三档素材响度一致，识别表现更稳定 |

#### 7. 术语与专有名词纠错（投入产出比最高）

| | 内容 |
|---|---|
| **问题** | 8 处实测错误中 4 处为专业课术语或人名（Codd、指针、耦合、增删改查） |
| **建议** | 以课件文本构建热词表，作为 `initial_prompt` 传入；短素材可配合 `small` 档 |
| **预期收益** | 直接纠正课程关键概念；**不需要更大的模型**，成本极低 |

#### 8. 幻觉与重复防护

| | 内容 |
|---|---|
| **问题** | 6 分钟素材 `compression_ratio` 已达 2.386（阈值 2.4）；另有单段 `no_speech_prob` 达 0.9779，模型认为该段无语音却仍输出文本 |
| **建议** | 把这两项指标纳入自动质检，超标即标记复核 |
| **预期收益** | 幻觉文本不会被当作正常字幕推给学生 |

#### 9. 模型档位按场景选择

| | 内容 |
|---|---|
| **问题** | `small` 在短素材更准（logprob −0.084 对 −0.144），但在 13 分钟素材上反而更差（−0.206 对 −0.150），且慢 2.3～2.8 倍 |
| **建议** | 短素材用 `small`、长素材用 `base`；**A/B 必须在固定线程数下进行** |
| **预期收益** | 在可接受的算力成本下取得整体最优准确度 |

### P2 · 多模态增强

#### 10. VAD 按素材特征自动开关

| | 内容 |
|---|---|
| **问题** | VAD 在静音轨上省 99.4%，在语音密集素材上反而慢 11%，一刀切无法兼顾 |
| **建议** | 以闸门给出的「有效帧占比」作为自动判断依据 |
| **预期收益** | 两端都拿到最优：静音不浪费算力，语音不被额外开销拖慢 |

#### 11. 抽帧 + OCR 补全课件侧

| | 内容 |
|---|---|
| **问题** | 时间轴 slides 恒为 1 条占位，从不来自视频本身；页面切换与课件内容完全未被利用 |
| **建议** | 按页面切换检测抽帧并 OCR |
| **预期收益** | 补全课件信息；同时**为第 7 项提供热词来源**，形成正向循环 |

#### 12. 双向对齐

| | 内容 |
|---|---|
| **问题** | 音频与画面两条信息流彼此独立，互不校正 |
| **建议** | 课件文字纠正转写错字；转写内容判断页面切换时刻；多人课程叠加说话人分离 |
| **预期收益** | 转写准确度与时间轴精度同时提升，是「多模态」的核心价值兑现 |

#### 13. 闸门向量化

| **预期收益** | 开销再降一到两个数量级，为超长录播留出余量 |

## 七、建议固化的验收基座

为让上述改动可度量，建议固定以下基线。**必须在固定线程数（可复现取值）下执行**，否则随机性会掩盖真实改动。

| 用途 | 素材 | 预期基线 |
|---|---|---|
| 快速回归 | 短片段 37s | 15 段 / 164 字 |
| 主力场景 | 正常短 6min | 37 段 / 1384 字 |
| 压力场景 | 正常长 13min | 77 段 / 2764 字 |
| 拒绝路径 | 「无音频」6min | `failed` · 闸门 0.42 s |

> 建议顺序：**先做 P0-1**，否则该基线的数字每次运行都可能变化，后续所有优化都无法验证收益。
